### Broker Configuration (For Real Kafka Setup):

**Create `broker_config.properties`:**
```
# Kafka Broker Configuration
broker.id=1
listeners=PLAINTEXT://172.28.128.2:9092
advertised.listeners=PLAINTEXT://172.28.128.2:9092
zookeeper.connect=172.28.128.2:2181

# Topics configuration
auto.create.topics.enable=false
```

**Create Topics:**
```bash
# Start Kafka broker
bin/kafka-server-start.sh config/server.properties

# Create topics on Broker Machine
bin/kafka-topics.sh --create --topic topic-cpu --partitions 1 --replication-factor 1 --bootstrap-server 172.28.128.2:9092
bin/kafka-topics.sh --create --topic topic-mem --partitions 1 --replication-factor 1 --bootstrap-server 172.28.128.2:9092
bin/kafka-topics.sh --create --topic topic-net --partitions 1 --replication-factor 1 --bootstrap-server 172.28.128.2:9092

```

**Producer Command (Run on Producer Machine):**

**Consumer Commands (Run on respective machines):**

## 5. Viva (Oral Examination)

### What is it?
A brief oral exam where you'll explain your implementation and understanding.

### Key Topics to Prepare:

**1. Architecture Understanding**
- Explain the producer-consumer pattern
- How Kafka topics work (topic-cpu, topic-mem, topic-net, topic-disk)
- Role of each machine
- Why windowed aggregation is used

**2. Implementation Details**
- Window parameters (30s window, 10s slide)
- How per-server computation works
- Aggregation methods (AVG for CPU+Memory, MAX for Network+Disk)
- Alert threshold logic

**3. Data Processing**
- How 28,800 input records become 14,400 output rows
- Calculation: 20 servers × 720 time windows = 14,400 rows
- Timestamp format (HH:MM:SS)
- Numeric precision (2 decimal places)

**4. Troubleshooting**
- If data mismatch occurs, what would you check?
- How to verify window boundaries are correct?
- How to debug sorting/filtering issues?

**5. Your Specific Dataset**
- Know your thresholds (cpu_threshold, mem_threshold, net_in_threshold, disk_io_threshold)
- Understand alert conditions for your data
- Be ready to explain output values

### Sample Q&A:

**Q: Why use sliding windows?**
A: To capture anomalies at different time intervals. A 30-second window with 10-second slide gives us overlapping windows that detect problems that might be missed with fixed windows.

**Q: How did you ensure 100% CPU is consumed?**
A: Since we have 20 servers and 720 time windows each, that's exactly 14,400 rows. Every server appears in every window window.

**Q: How would this scale to real Kafka?**
A: The pipeline logic stays the same. Instead of simulating topics, actual Kafka topics would feed data to consumers. ZeroTier enables machine-to-machine communication across distributed environments.
